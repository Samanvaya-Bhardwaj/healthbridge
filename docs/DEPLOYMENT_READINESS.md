## 2. Before every release (operator checklist)

1. **Gates:** `npm run check` is green on the commit, and CI is green on `main`.
2. **Environment preflight**, on the server, with the release images:

   ```bash
   node infra/deploy/preflight.mjs --env-file /etc/healthbridge/healthbridge.env \
     --backend-image ghcr.io/<owner>/healthbridge-backend:vX.Y.Z \
     --ai-image ghcr.io/<owner>/healthbridge-ai:vX.Y.Z
   ```

   It renders the deployment with `docker compose config`, so every required variable is
   checked as Compose sees it. It then validates the API, worker and migrate environments
   and the AI service settings inside their own images, and checks policy:
   - external AI approval and the spend ceiling;
   - HTTPS;
   - no demo data in production;
   - every secret different;
   - an off-site backup remote.

   It prints variable names and rules only, never values, and exits 1 on any failure.
   On ECS there is no env file: the services check their configuration at start-up, and
   the deployment circuit breaker rolls back a release whose tasks fail to start
   (OPERATIONS.md §3). Validate the secret's keys against the task definitions before
   tagging.
3. **Backup before migrating:** run the backup job and confirm it in the backup log. Then
   check pending migrations with
   `docker compose -f infra/deploy/compose.prod.yml --env-file … run --rm migrate node scripts/migrate.js status`.
4. **Deploy** (tag, or `HB_VERSION=vX.Y.Z … up -d --wait` on a single host).
5. **After deploying:**
   - `node infra/deploy/smoke.mjs https://<domain> --expect-version vX.Y.Z`;
   - `docker compose -f infra/deploy/compose.prod.yml --env-file … run --rm migrate node scripts/verify-audit.js`
     (the whole audit chain);
   - the Grafana overview and the Prometheus alerts are quiet.

## 4. Secrets and settings

`make-env.mjs` generates every internal secret: database, Redis and MinIO passwords,
internal service secret, JWT key, payment webhook secret, clinical data key, AI input
digest key, backup and Bull Board passwords. The operator adds the external ones in §1.

Keys that need special care:

| Key | Rule |
|---|---|
| `CLINICAL_DATA_KEY` | It encrypts clinical notes, and seals prescriptions and the audit log. Keep previous keys in `CLINICAL_DATA_PREVIOUS_KEYS` for as long as anything made with them exists (OPERATIONS.md §6). |
| `AI_INPUT_DIGEST_KEY` | Backend only; never given to the AI service. |
| Backup age identity | Offline. Keep it for as long as backups made with it are retained. |
| `LLM_DAILY_BUDGET_USD` | Required with an external model (default 20 in Compose and CD). |
