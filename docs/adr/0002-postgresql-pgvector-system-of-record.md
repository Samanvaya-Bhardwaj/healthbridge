# ADR-0002: PostgreSQL with pgvector as the single system of record

- **Status:** Accepted
- **Date:** 2026-10-01

## Context

We need relational integrity for clinical and financial data, full-text search, vector
search for patient-scoped retrieval, and row-level security. A separate vector database
would be a second store of medical content that has to be kept in sync and secured.

## Decision

- PostgreSQL 17 with the `pgvector`, `pgcrypto`, `citext`, `btree_gist` and `pg_trgm`
  extensions is the **only** system of record. Redis holds nothing that cannot be rebuilt.
- Use PostgreSQL-native features directly where they add value:
  - constraints and indexes;
  - exclusion constraints (no overlapping appointments);
  - row-level security;
  - transactions;
  - `tstzrange` and `vector`.
- Schemas: `public` (core), `ai` (AI artifacts), `audit` (append-only logs).
- Primary keys are UUIDv7, generated by the application.
- Large files are stored in object storage (ADR-0013), never in the database.

## Consequences

- One backup, restore, encryption and access-control story for all structured data.
- Embeddings and their source records live in the same transactional store.
- Vector search is per patient. Per-patient corpora are small, so filtered exact search is
  fast without a global ANN index (ADR-0010).
- Scaling path: read replicas and partitioned log tables before any extra datastore.
